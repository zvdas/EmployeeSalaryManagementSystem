# Design Notes

Planning notes written before implementation. This document is the **single source of truth for the API contract**. The backend and frontend are built in parallel (by separate AI agents) against it.

## 1. Approach
1. Requirements first ([01-requirements.md](01-requirements.md)).
2. Freeze the data model and API contract (this document).
3. Scaffold backend and frontend in parallel, in disjoint folders.
4. Build features in vertical milestones, adding tests with each one.
5. Integrate, harden, deploy, and document the trade-offs and performance.

## 2. Tech stack
| Layer | Choice | Reason |
|---|---|---|
| API | Node.js 22, Express, TypeScript | Required stack; TS shares typing discipline with Angular |
| DB | SQLite (better-sqlite3) | Zero-ops, a single file, fast in-memory test DBs. 10k rows is tiny for SQLite |
| Data access | Hand-written SQL in repository classes | Analytics SQL stays explicit; no ORM abstraction cost |
| Validation | zod | One schema drives runtime validation **and** the OpenAPI docs |
| API docs | @asteasolutions/zod-to-openapi + swagger-ui-express | Docs are generated from the code, so they cannot drift |
| UI | Angular (standalone + signals), Angular Material, ng2-charts | Required framework; Material provides table, paginator, sort and dialogs |
| Tests | Vitest + Supertest (API), Jest (UI) | Fast and deterministic |
| Hosting | Render blueprint (web service + static site) | Free tier; deploys from GitHub |

## 3. Domain model

### Reference data (code constants, mirrored into the DB)
**Countries.** `usdRate` is the USD value of 1 unit of local currency (static, dated 2026-10). The salary factor is the share of the US base salary paid in that country, before FX.

| code | name | currency | usdRate | salary factor (seed only) |
|---|---|---|---|---|
| US | United States | USD | 1.00 | 1.00 |
| GB | United Kingdom | GBP | 1.27 | 0.80 |
| DE | Germany | EUR | 1.08 | 0.80 |
| IN | India | INR | 0.012 | 0.30 |
| CA | Canada | CAD | 0.73 | 0.80 |
| AU | Australia | AUD | 0.66 | 0.85 |
| SG | Singapore | SGD | 0.74 | 0.80 |
| BR | Brazil | BRL | 0.18 | 0.35 |

**Departments and job titles.** Each job title belongs to exactly one department. Validation enforces this pairing so analytics stay consistent, which free text could not guarantee.

**Employment types:** `FULL_TIME`, `PART_TIME`, `CONTRACT`.

### Tables
```sql
countries (
  code TEXT PRIMARY KEY,          -- ISO 3166-1 alpha-2
  name TEXT NOT NULL,
  currency TEXT NOT NULL,         -- ISO 4217
  usd_rate REAL NOT NULL CHECK (usd_rate > 0)
)

employees (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  employee_code TEXT NOT NULL UNIQUE,     -- EMP-000001, generated by the server
  full_name TEXT NOT NULL,
  email TEXT NOT NULL UNIQUE COLLATE NOCASE,
  job_title TEXT NOT NULL,
  department TEXT NOT NULL,
  country_code TEXT NOT NULL REFERENCES countries(code),
  annual_salary INTEGER NOT NULL CHECK (annual_salary > 0),  -- whole units, local currency
  employment_type TEXT NOT NULL,
  hire_date TEXT NOT NULL,                -- YYYY-MM-DD
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at TEXT NOT NULL DEFAULT (datetime('now'))
)
CREATE INDEX idx_emp_country_title ON employees(country_code, job_title);
CREATE INDEX idx_emp_department    ON employees(department);
CREATE INDEX idx_emp_full_name     ON employees(full_name);
```
Salaries are integers in local currency. This avoids floating-point money; annual salaries do not need minor units. USD values are **derived** at query time (`annual_salary * usd_rate`) and never stored, so changing a rate needs no data migration.

## 4. API contract
Base path `/api`. JSON uses camelCase. Dev ports: API `3000`, UI `4200`.

### Error shape (every non-2xx response)
```json
{ "error": { "code": "VALIDATION_ERROR", "message": "Request validation failed", "details": [ { "path": "email", "message": "Invalid email" } ] } }
```
| Status | code |
|---|---|
| 400 | `VALIDATION_ERROR` |
| 413 | `VALIDATION_ERROR` (request body over 100 kB; kept as 413 because that is the correct HTTP status) |
| 404 | `NOT_FOUND` |
| 409 | `CONFLICT` |
| 500 | `INTERNAL_ERROR` |

### Types
```ts
type EmploymentType = 'FULL_TIME' | 'PART_TIME' | 'CONTRACT';

interface Employee {
  id: number;
  employeeCode: string;        // "EMP-000123"
  fullName: string;
  email: string;
  jobTitle: string;
  department: string;
  countryCode: string;         // "IN"
  currency: string;            // derived from country, e.g. "INR"
  annualSalary: number;        // local currency, integer
  annualSalaryUsd: number;     // derived, rounded to integer
  employmentType: EmploymentType;
  hireDate: string;            // "YYYY-MM-DD"
  createdAt: string;           // ISO-8601
  updatedAt: string;
}

// POST body (all required) and PUT body (all required, full replace)
interface EmployeeInput {
  fullName: string;            // 2..100 chars, trimmed
  email: string;               // valid email, unique (case-insensitive)
  jobTitle: string;            // must be a known title AND belong to `department`
  department: string;          // must be a known department
  countryCode: string;         // must exist in countries
  annualSalary: number;        // integer, 1..100,000,000
  employmentType: EmploymentType;
  hireDate: string;            // YYYY-MM-DD, not in the future
}

interface Paginated<T> { items: T[]; total: number; page: number; pageSize: number; }
```

### Endpoints
| Method & path | Request | Response |
|---|---|---|
| `GET /health` | – | `{ status: "ok" }` |
| `GET /docs` | – | Swagger UI |
| `GET /openapi.json` | – | OpenAPI 3 document |
| `GET /meta` | – | `{ countries: {code,name,currency,usdRate}[], departments: string[], jobTitles: {title,department}[], employmentTypes: EmploymentType[] }` |
| `GET /seed/status` | – | `{ employeeCount: number, isEmpty: boolean }` |
| `POST /seed` | `{ count: 100 \| 10000 }` | `201 { inserted: number }`. `409` if the DB already has employees |
| `GET /employees` | query: `search?` (name/email/code, case-insensitive contains), `country?`, `department?`, `jobTitle?`, `page=1`, `pageSize=25` (max 100), `sortBy=fullName` (one of `fullName, employeeCode, jobTitle, department, countryCode, annualSalaryUsd, hireDate`), `sortDir=asc\|desc` | `Paginated<Employee>` |
| `GET /employees/export.csv` | same filters as the list (no paging) | `text/csv` attachment `employees.csv`. Columns: `employeeCode,fullName,email,jobTitle,department,countryCode,currency,annualSalary,annualSalaryUsd,employmentType,hireDate` |
| `GET /employees/:id` | – | `Employee`, or 404 |
| `POST /employees` | `EmployeeInput` | `201 Employee` |
| `PUT /employees/:id` | `EmployeeInput` | `Employee`, 404, or 409 |
| `DELETE /employees/:id` | – | `204`, or 404 |
| `GET /insights/summary` | – | `{ headcount, totalPayrollUsd, avgSalaryUsd, medianSalaryUsd, countryCount, departmentCount }` |
| `GET /insights/by-country` | – | `{ countryCode, countryName, currency, headcount, minSalary, maxSalary, avgSalary, medianSalary, avgSalaryUsd, medianSalaryUsd, totalPayrollUsd }[]` (local amounts; sorted by headcount desc) |
| `GET /insights/by-job-title?country=XX` | `country` required | `{ jobTitle, department, currency, headcount, minSalary, maxSalary, avgSalary, medianSalary }[]` (local currency; sorted by avgSalary desc) |
| `GET /insights/by-department?country=XX` | `country` optional (omitted means the whole org) | `{ department, headcount, totalPayrollUsd, avgSalaryUsd, medianSalaryUsd }[]` (sorted by totalPayrollUsd desc) |
| `GET /insights/distribution?country=XX&buckets=10` | `country` optional, `buckets` 2..50 (default 10) | `{ currency: "USD", buckets: {min,max,count}[], outliers: { lowThreshold, highThreshold, lowCount, highCount } }` (outliers use the 1.5×IQR rule) |

All monetary averages and medians are rounded to integers.

## 5. Key design decisions
- **`createApp(db)` factory.** The DB is injected, so tests run against `:memory:` without mocks.
- **Layering is routes → service → repository.** Routes handle HTTP only. Services hold business rules (title/department pairing, uniqueness → 409). Repositories hold SQL only.
- **Medians are computed in TypeScript** (`lib/stats.ts`), because SQLite has no MEDIAN. For ≤10k rows, fetching sorted salaries per group costs milliseconds and keeps the logic pure and unit-testable.
- **Seed generator is a pure function** `generateEmployees(count, seed)` driven by the mulberry32 PRNG. The same seed always produces the same data, so tests can assert on it. Salary = base(title) × factor(country) × jitter(0.85–1.20) ÷ usdRate, rounded to the nearest 100.
- **Seeding is explicit, not automatic.** On load, the UI calls `/seed/status` and asks the user for 100 or 10,000 rows. `POST /seed` refuses to run on a non-empty DB, so real data can never be overwritten from the UI.
- **OpenAPI generated from zod.** The schema objects used by the `validate` middleware are the same ones registered with the OpenAPI registry.

## 6. Frontend design
- Routes: `/employees` (default), `/insights`. Lazy-loaded standalone components.
- `core/`: models (mirroring §4), API services, an error interceptor (snackbar showing `error.message`), and the seed-prompt service.
- `features/employees/`: list (mat-table, server-side paginator and sort, filter selects, 300 ms debounced search, export button) and form dialog (reactive form; the job title options are filtered by department; the currency label follows the country).
- `features/insights/`: KPI cards, by-country table + bar chart (avg vs median USD), a job-title lookup with a country select, a department table + chart, and a distribution histogram with a country filter.
- `environment.apiUrl`: `http://localhost:3000/api` in dev; injected at build time for production.
